## Why FoundationForecast?

The time series forecasting landscape has entered its foundation era — but every lab ships its own API, dependencies, and data conventions. Comparing models fairly or combining them in production is needlessly difficult.

FoundationForecast removes that friction:

<CardGroup cols={3}>
  <Card title="One Interface" icon="plug">
    `FoundationForecast` runs Chronos, Moirai, TimesFM, Toto, TiRex, TimeGPT, and 6 more through identical `forecast()`, `cross_validation()`, and `detect_anomalies()` calls.
  </Card>
  <Card title="Exogenous Variables" icon="table">
    Pass known-future covariates via `X_df` on supported checkpoints: Chronos-2, TimesFM-3, TimeGPT, T0, and TiRex-2.
  </Card>
  <Card title="GPU-Native" icon="microchip">
    Automatically runs on GPU when available — no per-model device configuration needed.
  </Card>
</CardGroup>

## Quick Example

```python
import pandas as pd
from foundationforecast import FoundationForecast
from foundationforecast.models import Chronos, Toto

df = pd.read_csv(
    "https://timecopilot.s3.amazonaws.com/public/data/entsoe_4markets_8w.csv",
    parse_dates=["ds"],
)

ff = FoundationForecast(
    models=[
        Chronos(repo_id="amazon/chronos-bolt-tiny", alias="Chronos"),
        Toto(context_length=512, alias="Toto"),
    ]
)

fcst_df = ff.forecast(df, h=24, level=[90])
cv_df = ff.cross_validation(df, h=24, level=[90])
anomalies_df = ff.detect_anomalies(df, level=99)
```

<Note>
  Your DataFrame needs three columns: `unique_id`, `ds`, and `y`. Pass `parse_dates=["ds"]` when reading CSVs to ensure correct datetime sorting.
</Note>
