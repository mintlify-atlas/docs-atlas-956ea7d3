## v0.1.11

### Features

**Known-future exogenous variables (`X_df`, `futr_exog_list`)** — Pass covariates for the forecast horizon via `FoundationForecast.forecast(..., X_df=..., futr_exog_list=...)`. With the default `exog_strategy="auto"`, only checkpoints that support **native** futr exog consume `X_df`; others raise `ValueError`. Use `exog_strategy=False` to silently ignore horizon exog in multi-model runs.

```python
import pandas as pd
from foundationforecast.models import Chronos

df = pd.read_parquet(
    "https://timecopilot.s3.amazonaws.com/public/data/electricity_price/train.parquet"
)
X_df = pd.read_parquet(
    "https://timecopilot.s3.amazonaws.com/public/data/electricity_price/futr_exog.parquet"
)

model = Chronos(repo_id="amazon/chronos-2", alias="Chronos-2")
fcst = model.forecast(df=df, h=24, X_df=X_df)
assert "Chronos-2" in fcst.columns
```

**Native futr exog** is now supported on Chronos-2, TimesFM-3, TimeGPT, T0 (beta), and TiRex-2, with up-front validation that horizon exog covers every series and matches `futr_exog_list` before multi-model dispatch.

**`experiments/fev-bench`** — Added a known-dynamic-only fev-bench grid (13 tasks) with Modal CI replication for Chronos-2, TimesFM-3, T0-beta, and TiRex-2 on `epf_pjm` and `entsoe_1H`, mirroring the gift-eval experiment layout.

### Fixes

- **TimesFM-3 fev-bench replication**: Set `context_length=15360` in fev-bench config. The official submission uses long context; the default of 2048 truncated ENTSO-E history.
- **Chronos native exog**: Always request the median quantile for point forecasts when using covariates.
- **Multi-model exog**: Validate exog support up front; omit exog kwargs when horizon data is missing.
- **Exog validation**: Reject duplicate horizon keys, missing series in `X_df`, invalid `exog_strategy`, and inconsistent `futr_exog_list` / horizon coverage before forecast dispatch.

### Documentation

- New [Exogenous variables](https://foundationforecast.mintlify.app/exogenous-variables) guide, README support matrix, and `exogenous-variables.ipynb` example notebook.
- README header images now hosted on GitHub for reliable PyPI rendering.

### Tooling

- Pre-commit **mypy** excludes `experiments/` so gift-eval and fev-bench `src` trees do not collide.

**Full Changelog**: https://github.com/TimeCopilot/foundationforecast/compare/v0.1.10...v0.1.11

## Previous Releases

<Accordion title="v0.1.10 — Quantile column naming fix">

### Fixes

- **Quantile column suffixes**: Output columns now use minimal decimal text for `100 × quantile` — for example `0.57` → `{alias}-q-57`, `0.151` → `{alias}-q-15.1`, and level-derived `0.975` → `{alias}-q-97.5` during conversion. The previous behaviour used `int(100 × quantile)` or rounded centile suffixes, which caused collisions for multi-`level` requests (e.g. `level=[95, 97]`) or truncated float noise (`Chronos-q-56` for `0.57`).
- **`quantiles=` validation**: User-provided `quantiles` may have up to three decimal places with unique suffixes; duplicate mappings now raise instead of silently overwriting columns in GluonTS paths.
- **`level=` validation**: Confidence levels must be **integer** percents; fractional `level` values are now rejected.

**Full Changelog**: https://github.com/TimeCopilot/foundationforecast/compare/v0.1.9...v0.1.10

</Accordion>

<Accordion title="v0.1.9 — Quantile interpolation for arbitrary levels">

### Features

**Quantile interpolation for arbitrary `level` and `quantiles`** — Fixed-knot models (TiRex, TimesFM, TabPFN, FlowState, Tafsut, Toto 2.0, and others) always run their native quantile knots, then linearly interpolate (with edge clamping) to any requested prediction level or quantile. PatchTST-FM continues to evaluate quantiles natively in the 0.01–0.99 range.

```python
import pandas as pd
from foundationforecast.models.tirex import TiRex

df = pd.read_csv(
    "https://timecopilot.s3.amazonaws.com/public/data/air_passengers.csv",
    parse_dates=["ds"],
)
model = TiRex()
fcst = model.forecast(df, h=12, freq="MS", level=[50, 80])
assert "TiRex-lo-50" in fcst.columns
```

**`foundationforecast.core.quantiles`** — New shared helpers (`interpolate_quantiles`, `resolve_quantile_values`, `backend_quantile_levels`, `select_clipped_quantile_values`) and documentation for edge clamping when requests fall outside a model's supported quantile range. Output column names always reflect the user's request.

**PatchTST-FM family example notebook** — Added `patchtst-fm-family.ipynb` comparing IBM Research and Granite PatchTST-FM r1/r2 checkpoints.

### Fixes

- **Removed undocumented `level=0` sentinel**: Point forecasts always appear in the model alias column; pass standard `level` values or `quantiles=` directly.
- **TimesFM v1**: Restore default quantiles on point-only forecasts; strip native q-columns before assigning interpolated output.
- **FlowState / TimesFM v2–v3**: Drop legacy exact-length quantile guards in favour of interpolation.
- **Chronos**: Map clipped quantiles on the last axis after batching `(batch, horizon, n_quantiles)` tensors.
- **Duplicate quantile columns**: Reject requests whose `int(100 × quantile)` suffixes collide (e.g. `0.151` and `0.159`).

### Documentation

- Expanded Probabilistic forecasting docs with interpolation, edge clamping, and native-backend clamping behaviour.
- Updated TiRex, TimesFM, TabPFN, and related family notebooks for the new API.

**Full Changelog**: https://github.com/TimeCopilot/foundationforecast/compare/v0.1.8...v0.1.9

</Accordion>

<Accordion title="v0.1.8 — Granite PatchTST-FM r2, T0 beta, TiRex-2, shared panel processing">

### Features

**Granite PatchTST-FM r2** — The shared `PatchTSTFM` wrapper now supports [`ibm-granite/granite-timeseries-patchtst-fm-r2`](https://huggingface.co/ibm-granite/granite-timeseries-patchtst-fm-r2) (~385M). r2 adds Conformer blocks, overlapping patches (`patch_stride=8`), and a 99-quantile head on top of r1. Requires `granite-tsfm>=0.3.9`. GIFT-Eval CI replicates `Granite-PatchTST-FM-r2` on `m4_weekly/short`.

```python
import pandas as pd
from foundationforecast.models.patchtst_fm import PatchTSTFM

df = pd.read_csv(
    "https://timecopilot.s3.amazonaws.com/public/data/air_passengers.csv",
    parse_dates=["ds"],
)
model = PatchTSTFM(
    repo_id="ibm-granite/granite-timeseries-patchtst-fm-r2",
    alias="Granite-PatchTST-FM-r2",
    context_length=8192,
    batch_size=32,
)
fcst = model.forecast(df, h=12, freq="MS")
assert "Granite-PatchTST-FM-r2" in fcst.columns
```

**T0 beta** — The `T0` wrapper now works with [`theforecastingcompany/t0-beta`](https://huggingface.co/theforecastingcompany/t0-beta) (~256M).

```python
import pandas as pd
from foundationforecast.models.t0 import T0

df = pd.read_csv(
    "https://timecopilot.s3.amazonaws.com/public/data/air_passengers.csv",
    parse_dates=["ds"],
)
model = T0(
    repo_id="theforecastingcompany/t0-beta",
    alias="t0-beta",
)
fcst = model.forecast(df, h=12, freq="D", quantiles=[0.1, 0.5, 0.9])
assert "t0-beta" in fcst.columns
```

**Shared panel processing** — Forecasters reuse a common panel path for multi-series inputs (Chronos, TimesFM, Tafsut, and others), reducing redundant work and improving multi-model orchestration throughput.

### Fixes

- **FlowState frequency aliases**: Normalise pandas-inferred aliases (`h`, `6h`, `15min`, `MS`) before calling `granite-tsfm` `get_fixed_factor`, so hourly and month-start series work when `freq` is omitted.
- **T0 / gift-eval CI**: Bumped `tfc-t0` to `>=0.5.0` and call `T0Forecaster.predict(quantile_levels=...)` instead of the removed `quantiles=` kwarg.

### Dependencies

- Bumped `tfc-t0` from `>=0.2.3` to `>=0.5.0` (required for t0-beta; still supports t0-alpha).
- Replaced `timecopilot-granite-tsfm` with `granite-tsfm>=0.3.9` (required for PatchTST-FM r2 overlapping-patch inference).

**Full Changelog**: https://github.com/TimeCopilot/foundationforecast/compare/v0.1.7...v0.1.8

<Accordion title="v0.1.6 — TabPFN-3 support">

import pandas as pd
from tabpfn_time_series import TabPFNMode
from foundationforecast.models.tabpfn import TABPFN_V2_MODEL, TABPFN_V3_MODEL, TabPFN

df = pd.read_csv(

model = TabPFN(
    model_path=TABPFN_V3_MODEL,

    context_length=32768,

assert model.model_path == TABPFN_V3_MODEL

<Accordion title="v0.1.5 — Model weight cache and CodSpeed benchmarks">

### Features

**Model weight cache** — All local weight-loading forecasters reuse loaded weights across repeated `forecast()` calls via a process-wide LRU cache on the base `Forecaster` (default `max_cached_models=1`). Configure with `set_max_cached_models()` or opt out per forecaster with `reuse_loaded_model=False`.

**`clear_model_cache()`** — All forecasters now expose `clear_model_cache()`. Pass `clean_cache=True` to `FoundationForecast` to call it after each model in multi-model runs to limit GPU memory use.

**CodSpeed benchmarks** — Added `pytest-codspeed` and a `benchmark` pytest marker (excluded from the default test run). Core benchmarks cover `maybe_infer_freq`, `TimeSeriesDataset`, `QuantileConverter`, and `SeasonalNaiveModel`; model benchmarks cover Chronos-Bolt, TimesFM 1.0, Toto, and Moirai 1.1. A dedicated `.github/workflows/codspeed.yml` workflow runs simulation benchmarks for core code and walltime/macro benchmarks for models in CI.

**Full Changelog**: https://github.com/TimeCopilot/foundationforecast/compare/v0.1.4...v0.1.5

</Accordion>

<Accordion title="v0.1.3 — TimesFM 3.0 support">

### Features

**TimesFM 3.0 foundation model** — Added support for [`google/timesfm-3.0-pytorch`](https://huggingface.co/google/timesfm-3.0-pytorch) via a new `_TimesFMV3` backend powered by `TimesFM3Evaluator` and `ModelConfig` from `timecopilot-timesfm>=0.4.0`. The wrapper treats each series independently (univariate panel mode), matching the existing TimesFM 2.5 integration pattern.

```python
import pandas as pd
from foundationforecast import TimesFM

df = pd.read_csv(
    "https://timecopilot.s3.amazonaws.com/public/data/air_passengers.csv",
    parse_dates=["ds"],
)

model = TimesFM(
    repo_id="google/timesfm-3.0-pytorch",
    alias="TimesFM-3",
    context_length=2048,
)
fcst_df = model.forecast(df, h=12, freq="MS")
```
